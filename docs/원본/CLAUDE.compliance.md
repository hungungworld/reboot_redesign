# CLAUDE.md · ALDICOM 컴플라이언스·CS 대시보드 (3조)

> Claude Code가 이 폴더에서 일할 때 매번 먼저 읽는 프로젝트 설명서입니다.
> 사람이 바꿀 때는 팀 단톡에 먼저 알리고 고칩니다.

## 상황
- 알디콤을 모티브로 한 신규 숙취해소 젤리 스틱의 미국 수출용 마케팅 대시보드
- 내 파트: **컴플라이언스(광고 문구 점검)** + **CS(고객 문의 응대)**
- 기준 파일: `dashboard.html` (ALDICOM · Compliance & CS)
- 가져올 자료: `_incoming/fda_ad_console/` (FDA 광고 콘솔 zip을 푼 것)
- 조원들과 VS Code + GitHub로 같이 작업함
- 작업자는 코딩 비전공자 → 설명은 쉬운 말로

## 이미 정한 것 (바꾸지 않음)
- 미국 제품 분류는 **일반식품(Conventional Food)**. 건강기능식품(Dietary Supplement)은 비교용 옵션일 뿐
- 규칙 번호는 **dashboard.html의 R1~R10이 기준**. zip의 R0~R12는 번호를 버리고 R1~R10 아래로 다시 묶음
  - R1 질병·치료 클레임 · R2 'hangover' 직접 언급 · R3 안전성 보장·간 보호 · R4 알코올 홍조·ALDH2
  - R5 효과 보장·과장 · R6 음주 조장 · R7 의약품 오인 · R8 구조·기능 클레임 · R9 인체적용시험 인용 · R10 후기·리뷰
- 판정 단계는 dashboard 5단계 그대로: BLOCK(사용 불가) · REVISE(수정 필요) · COND(조건부) · REVIEW(검토 필요) · PASS(규칙 미탐지)
- 'BLOCK' 판정 문구는 승인 불가, CS 답장도 BLOCK이면 발송 불가
- 판정은 1차 참고용. 최종 판단은 사람(법무·컴플라이언스 담당)

## 목적
- zip의 좋은 점(경고장 크롤링, 원문 87개, 규제 단어 57개, openFDA 재시도, 테스트)을 dashboard에 합치기
- 합친 뒤에도 기존 정답이 깨지지 않을 것: 경고장 문구는 PASS 0개, 안전 문구 8개는 전부 PASS

## 지킬 것 (제약)
- **기존 메뉴·화면·디자인·CS 기능은 바꾸지 않는다.** 요청한 부분만 고친다
- 파일을 고치기 전에 무엇을 왜 바꾸는지 먼저 설명하고 허락을 받는다
- 한 번에 한 가지 작업만. 작업마다 새 브랜치 (`feat/compliance-…`)
- 내 파트(컴플라이언스·CS) 파일만 수정. 다른 조원 파일은 열어 보기만
- 사실·숫자·FDA 문구를 지어내지 않는다. 모르면 `{확인 필요}`로 남긴다
- FDA 경고장 인용 문구는 원문 그대로 (대괄호 `[]`, `. . .`도 원문 표기)
- API 키·비밀번호는 코드에 넣지 않는다. `.env`에만 두고 `.gitignore`로 막는다
- fda.gov 크롤링은 요청 사이에 충분히 쉬고(기본 30초), 서버에서만 실행한다

## 원하지 않는 것
- npm·React 같은 새 도구 도입 (지금 구조 유지)
- 규칙을 사람 확인 없이 자동으로 바꾸는 기능
- 우리 제품 성분명(헛개 등)을 사실대로 적었을 뿐인데 막히는 오탐
- 긴 설명. 바뀐 점은 3줄 요약 + 표

## 작업이 끝날 때마다 보고 형식
1. 바뀐 파일 목록
2. 바뀐 점 3줄
3. 검증 결과 숫자 (경고장 문구 탐지 수 / 안전 문구 PASS 수)
4. 사람이 결정해야 할 것 (있으면)
