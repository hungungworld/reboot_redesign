이 문서는 콘텐츠 제작 모듈의 화면, 대화 규칙, 데이터, API 연결 및 완료 기준을 정의한다. 실행 프로그램이나 실제 API 연동 완료 보고서가 아니다. 기술 선택의 이유와 발표 자료, PDF에서 정리한 프롬프트 로그는 [챗봇 구성 설명서](챗봇_구성_설명서.md)를 함께 참고한다.

## 2. 화면과 제작 시작

### 2.1 두 개의 하위 탭

| 탭 | 역할 |
| --- | --- |
| AI와 함께 제작 | 간단한 시트 → 대화 → 초안·이미지·영상 생성 → 수정 |
| 내 캠페인 | 목록·검색 → 대화와 상태 복원 → 버전 비교·최종본·다운로드 |

카피, CRM, 이미지 등의 기능은 콘텐츠 종류와 결과물 카드로 제공한다. 이들을 별도 상위 하위 탭으로 다시 늘리지 않는다.

### 2.2 기본 정보 시트: 다섯 항목

| 항목 | 입력 | 필수 | 처리 |
| --- | --- | --- | --- |
| 만들 콘텐츠 | 이미지 / 카드뉴스 / 숏폼 영상 / CRM 메시지 | 예 | 한 작업의 주 콘텐츠 하나 |
| 게시 채널 | Instagram / TikTok / Amazon / Weee / Yami / Global Olive Young / CRM | 예 | **하나만**. CRM 메시지 ↔ CRM 채널끼리만 (나머지 조합은 자유) |
| 제작 대상 | Reboot 브랜드 자체 + 제품 4종 체크박스 | 예 | 하나 이상. 제품 복수 선택 가능 |
| 목적 | 브랜드 알리기 / 제품 소개 / 구매 유도 / 재구매 / AI 추천 + 입력 칸 | 아니요 | 고른 칩을 다시 누르면 해제. 입력 칸에 직접 쓰거나 비워 두면 챗봇과 논의. `AI 추천` 버튼으로 후보 3개와 짧은 이유 제공 |
| 추가 요청 | 짧은 자유 입력 | 아니요 | 예: “검정 배경, 두 제품을 같이, 영어로” |

2026-10-24 변경: 상품 설명 · 캠페인 기획서는 없앴다. 예전에 만든 해당 캠페인은 DB에서 지우지 않고 목록 · 열기에서만 숨긴다(`options.RETIRED_TYPES`). Yami는 다른 탭과 같은 채널 ID `yamibuy`를 그대로 쓰고 표시 이름만 Yami다. Global Olive Young(`oliveyoung`)의 컴플라이언스 검사는 별도 규칙 확인 전까지 `b2c` 규칙으로 한다. 시트에서 CRM 메시지를 고르면 채널이 CRM으로, CRM 채널을 고르면 콘텐츠가 CRM 메시지로 맞춰진다.

시트 아래에는 선택한 정보 요약과 `이 정보로 시작`(질문 카드로 시작) · `질문 없이 바로 3안`(2026-10-25 추가) 버튼을 둔다. `질문 없이 바로 3안`은 캠페인을 만든 뒤 질문 없이 바로 `초안 만들기`(결과 칸 버튼과 같은 경로, 안 수는 AI 설정의 제안 수)를 실행한다. 이미지 콘텐츠는 카피 3안까지만 만들고, 비용이 드는 이미지 생성은 자동으로 하지 않는다. OpenAI 키가 없으면 이 버튼은 꺼진다. 캠페인명은 자동 임시 이름을 부여하고 나중에 바꾼다. 별도 캠페인명 입력을 시작 조건으로 두지 않는다.

참고 이미지·기존 카피는 선택적으로 첨부할 수 있도록 접어 둔다. CRM 이메일/SMS, 이미지 비율, 영상 길이, 언어, 타깃 등은 이 시트의 필수 항목으로 추가하지 않는다. 실제 작업에 필요하면 대화 또는 생성 카드에서 짧게 정한다.

`콘텐츠 / 채널 / 대상`을 고르면 시작할 수 있다. 목적이 비어 있어도 방향을 제안하며 시작한다. 시트가 비어 있다는 이유만으로 모든 추가 정보를 채우게 하지 않는다.

### 2.3 AI 추천

- `AI 추천` (목적 선택 버튼 줄의 마지막 버튼): 현재 콘텐츠·채널·대상에 맞는 목적 3개를 보여준다.
- `추가 요청 아이디어`: 예시 방향 3개를 보여주며 선택한 것만 입력 칸에 넣는다.
- 목적을 비워 두면 미정으로 유지하고 대화로 넘어간다. (2026-10-25: `직접 입력` · `챗봇과 논의하기` 칩은 입력 칸 · 빈 값과 같은 동작이라 없앴다.)
- 추천은 적용 전까지 제안이다. 직접 적은 문장을 자동으로 덮어쓰지 않는다.
- 추천 도중 대상이나 채널이 바뀌면 이전 조건의 추천은 자동 적용하지 않는다.
- 성분, 가격, 효능, 수치, 실제 판매 성과를 추천으로 만들어 채우지 않는다.

예: 브랜드 자체 + Instagram 이미지 선택 시 `브랜드 첫인상 알리기 / 슬로건 소개 / 브랜드 색상 소개`를 제안할 수 있다. 이것은 제작 아이디어이며 시장 분석 결과가 아니다.

젤리 맛과 모양: 체리 = 모자(분홍), 레몬 = 올가미(노랑), 라임 = 부츠(연두). Balance는 연한 색, Original은 진한 색이다. 봉지 안 젤리 개수와 성분 함량은 미제공이다. 뒷면 영양 정보는 이미지 참고용이며 카피에 쓰지 않는다. 일부 사진에 보이는 리볼버 모양은 확정 모양이 아니라서 생성 참고 사진에서 뺀다.

**적용 방식** — 공용 팩트시트(`data/products.json` · 설정 › 제품 정보)는 다른 탭도 쓰므로 콘텐츠 탭에서 고치지 않는다. 콘텐츠 제작 때만 `tabs/content/data/brand_kit.json`의 값을 제품별로 덮어쓴다(`brandkit.py`, `facts_version` 끝에 `+kit-2026-10-24`). 다른 탭과 맞추려면 설정 › 제품 정보에서 같은 값을 입력한다.

### 3.3 복수 대상과 브랜드 선택

제작 대상 체크박스는 `Reboot 브랜드 자체`와 위 제품 4종, 총 5개다. 어느 조합이든 하나 이상 선택할 수 있다.

| 선택 예 | 챗봇의 해석 |
| --- | --- |
| 브랜드 자체만 | 브랜드 소개·슬로건·색상 중심. 제품 선택을 다시 요구하지 않음 |
| Jelly Original + Drink Original | 두 제품이 함께 등장하는 제작. 서로의 정보를 분리해 사용 |
| 브랜드 자체 + Jelly Balance | 브랜드 메시지와 해당 제품 소개를 연결 |
| 제품 4종 | 라인업 콘텐츠. 공통 사실과 제품별 차이를 구분 |

브랜드 정보는 어떤 제품을 선택해도 공통 맥락으로 주입한다. `브랜드 자체` 체크는 브랜드를 콘텐츠의 주제로 삼는다는 뜻이며, 제품 4종을 자동 선택한다는 뜻이 아니다. 데이터에는 `brand_focus: boolean`과 `product_ids: string[]`를 분리해 저장한다. `brand_focus == true` 또는 `product_ids`가 비어 있지 않으면 대상 선택 조건을 충족한다.

### 3.4 사실 상태와 사용 범위

각 사실에 `fact_id`, `entity_id`, `value`, `source`, `status`, `facts_version`, `public_copy_status`를 둔다. 초기 출처는 `사용자 제공 / 2026-10-23`이다. 이는 시험성적서나 외부 검증을 확보했다는 뜻이 아니다.

사실 상태의 초기 내부 값은 `user_provided`(사용자 제공), `provisional`(임시), `development_goal`(개발 목표), `unknown`(미제공)으로 구분한다. 이 상태와 외부 카피 사용 가능 여부는 별도 필드다.

- 브랜드명·슬로건·제품명·제형·포장·맛·가격·용량(음료 100ml): 브랜드 키트(2026-10-24) 기준으로 카피에 쓸 수 있다.
- ZERO SUGAR: `zero_sugar: true`인 Balance 2종에만 "Zero Sugar"로 쓴다. Original·브랜드 전체에는 쓰지 않는다. 다른 당 표현(low sugar·sugar free 등)과 당·영양 수치는 쓰지 않는다. 콘텐츠 탭의 키워드 확인은 "Zero Sugar"에 경고를 띄우지 않는다(컴플라이언스 탭 결과는 그대로 표시).
- 효능·인증·성분 함량·젤리 봉지 안 개수: 미제공. `null` 또는 확인 필요.
- 복수 제품의 근거는 `{entity_id, fact_id}`로 연결한다. 한 제품의 값(가격·ZERO SUGAR 등)을 다른 제품이나 브랜드 전체로 복사하지 않는다.

사용자가 대화에서 캠페인 분위기를 바꾸는 것과 제품 사실을 바꾸는 것은 별개다. 제품 사실 변경 요청은 확인 대기 기록으로 남기며 채팅만으로 공통 팩트시트를 덮어쓰지 않는다.

### 3.5 브랜드 자산과 캐릭터 Rebu 선택 (2026-10-24 추가)

| 항목 | 내용 |
| --- | --- |
| 사진 | `tabs/content/data/assets/` — 로고 3 · 음료 22 · 젤리 15 · 캐릭터 7 (긴 쪽 2000px JPG · 시트 썸네일 `rebu-thumb` 256px는 보기용) |
| 목록 | `assets/manifest.json` — 사진마다 제품 · 맛 · 각도 · 설명 · `ref`(생성 참고 사진으로 쓸지) · `priority` |
| 화면 주소 | `GET /api/content/assets` (목록) · `/api/content/assets/<ID>.jpg` (로그인 필요) |
| 시트 칸 | 이미지 · 카드뉴스 · 숏폼일 때 **캐릭터 Rebu: 사용 / 사용 안 함 / AI 판단** → 결정 사항 `use_character`(확정)로 저장. 시작 후 시트 수정·대화로도 바꿀 수 있다 |

이미지 생성 때 서버가 선택 제품 · 맛 · Rebu 사용 여부에 맞는 사진을 골라 참고 이미지로 함께 보낸다 (`assets.pick_refs`). 2026-10-25부터 장수 제한 없이 **맞는 사진 전부**(맛을 정했으면 그 맛 사진 + 맛 구분 없는 3병·봉지 사진)를 보내고, Rebu를 쓰면 캐릭터 시트 1장을 더한다. 상한은 OpenAI 이미지 편집이 받는 **16장**(`assets.MAX_REFS`, 편집 기준 이미지 포함)이며 여러 제품이면 번갈아 넣어 제품마다 고르게 들어간다. Higgsfield(이미지 · 영상)는 참고 사진 상한을 확인하지 못해 예전처럼 5장(`HIGGSFIELD_MAX_REFS`)이다. 사진이 많을수록 생성 시간·비용이 늘 수 있다. 맛은 사용자가 말한 맛을 먼저 따르고, 없으면 프롬프트 작성 AI가 고른 맛을 따른다. 리볼버가 보이는 사진과 글자가 많은 캐릭터 시트(`ref: false`)는 고르지 않는다. 카드뉴스 Visual note와 숏폼 '기준 자산' 칸에는 자산 ID를 적어서, 나중에 영상 생성(Higgsfield)을 연결할 때 첫 장면·참고 이미지로 쓸 수 있게 한다.

## 4. 단순한 AI 설정

### 4.1 사용자에게 보이는 선택

| 설정 | 역할 | 노출 시점 |
| --- | --- | --- |
| **대화·제작 AI** | 대화, 추천, 기획, 카피, 대본, 브랜드·근거 보조 검토 | 기본 설정에 모델 선택 하나 |
| **이미지 AI** | 이미지 생성·지원 편집 | 이미지 작업 시 제공사 + 모델 |
| **영상 AI** | 영상 생성 | 실제 영상 생성 선택 시 Higgsfield 모델 |

대화 모델·기획 모델·검토 모델을 따로 고르게 하지 않는다. 같은 텍스트 모델을 사용하되 작업별 지침과 입력·출력 구조를 바꿔 호출한다. 같은 모델의 자체 검토는 보조 수단이며 독립적인 사실 검증으로 표시하지 않는다.

기본 실행 설정은 `대화·제작 AI` 하나와 연결 상태다. 이미지·영상 모델은 해당 작업에 필요한 경우에만 펼친다. 모델명은 실제 계정 접근과 기능 확인을 거친 카탈로그에서 선택한다. 첨부 과거 문서의 모델 ID를 검증 없이 기본값으로 복사하지 않는다.

### 4.2 접어 두는 고급 옵션

| 옵션 | 초기 제안값 |
| --- | --- |
| 답변 길이 | 짧게 |
| 콘셉트·카피 제안 수 | 3개 |
| 텍스트 자동 재작성 | 최대 1회, 0~2회 조절 |
| 영상 모드 | 구성안만 / 실제 생성 |

temperature, reasoning 등 SDK 파라미터는 일반 사용자에게 필수 설정으로 제시하지 않는다. 필요한 관리자 화면에서 해당 모델이 지원하는 값만 사용한다. 이미지·영상의 유료 재생성은 텍스트 자동 재작성 횟수에 포함해 자동 실행하지 않는다.

이미지 비율·조명·구도·인물·자막·카메라 움직임은 콘텐츠 표현 값이다. 채팅 또는 생성 카드에서 조절하며 모델 선택 화면에 모두 몰아넣지 않는다.

## 5. 시트를 인지하는 챗봇

### 5.1 권장 구현

**LangChain은 필수가 아니다. 권장안은 LangGraph 상태 제어 + OpenAI 공식 SDK + Higgsfield 어댑터다.** LangChain의 모델 래퍼·도구 래퍼는 팀에 필요할 때만 추가한다. 하나의 대화 AI가 작업별 프롬프트를 사용하며, 여러 자율 에이전트가 토론하는 구조는 도입하지 않는다.

LangGraph는 대화 상태와 조건 분기·재개 지점을 관리한다. 제품 사실·버전·파일·생성 작업은 대시보드 서버가 관리한다. LangGraph 체크포인트만으로 외부 생성 작업이나 업무 DB의 중복 처리가 해결되는 것으로 가정하지 않는다. 선택 이유·대안 비교는 설명서 2장을 참고한다.

### 5.2 매 턴 전달하는 맥락

1. 공통 대화 규칙과 Reboot 브랜드 기준.
2. 현재 캠페인의 시트 최신 리비전.
3. 선택 제품별 사실과 상태, 또는 브랜드 자체 맥락.
4. 확정·제안·미정 결정 사항과 최근 변경 이력.
5. 관련된 내부 MD 지침 하나 또는 필요한 조합.
6. 최근 대화·오래된 대화의 요약, 기준 결과물 버전과 실제 참고 파일.

시트는 첫 메시지에만 붙이지 않는다. 이후 매 턴 서버에서 최신 값을 다시 읽는다. 시트를 수정하면 다음 대화부터 새 값이 반영된다. 채팅에서 명확히 변경한 목적·대상·채널은 같은 서버 상태에 저장하여 시트와 오른쪽 패널도 함께 갱신한다.

첫 답변은 입력을 짧게 확인하고 바로 방향을 제안하거나, 꼭 필요한 질문 하나만 한다. 예: “젤리와 음료를 함께 보여주는 인스타 이미지로 시작할게요. 검정 배경에 네온 포인트를 넣는 방향을 제안합니다.” 목적을 이미 구매 유도로 입력했다면 목적을 다시 묻지 않는다.

### 5.3 유연한 대화 흐름

`333README(1).md`의 **4장 챗봇 상태머신**에서 다음 흐름만 참고한다. 그 파일의 제품 데이터, 7개 탭, 역할별 모델, 단일 제품 제한, 과거 규제 문구와 예시는 가져오지 않는다.

| 참고한 흐름 | 이번 적용 |
| --- | --- |
| 제품 → 채널 → 유형 | 시작 시트로 선입력, 대화 중 변경 가능 |
| 원문 입력 / 처음부터 | 기존 카피·참고 자료가 있을 때만 입력·사전 확인 |
| 부족한 정보 질문 | 시작 직후부터 **하나로 합친 대화**(5.5): 콘텐츠별 흐름 가이드를 따라 한 번에 핵심 질문 하나, 열린 질문 기본 + 필요할 때 보기 칩 |
| 미니 기획서 | 오른쪽 현재 방향 요약으로 통합, 매번 승인 단계로 막지 않음 |
| 초안 생성 → 사후 확인 | 요청한 초안 작성 후 브랜드·사실 보조 검토 |
| 크리에이티브 | 이미지·영상 작업일 때만 실행 |
| 특정 안 수정 → 재확인 | 선택한 문구·장·장면·이미지 버전만 수정 |
| 패키지 | 기존 내 캠페인 저장·다운로드로 연결 |

대화 단계는 체크리스트이며 모든 사용자가 통과해야 하는 설문 순서가 아니다. `질문 / 추천 / 결정 변경 / 초안 작성 / 이미지 생성 / 편집 / 버전 비교 / 저장` 의도를 구분해 다음 행동을 정한다.

예: 충분한 요청을 입력하고 “바로 만들어줘”라고 하면 기획서 확인 질문을 반복하지 않는다. “왜 이 색이 좋아?”는 설명만 하고 생성하지 않는다. “일단 이미지는 말고 카피만”은 이미지 작업을 만들지 않는다. “아까 B안으로 돌아가자”는 선택 버전을 바꾸며 전체 작업을 초기화하지 않는다.

모호한 “좋네”만으로 유료 영상 생성이나 제안 전체 확정을 실행하지 않는다. 단, 바로 앞 AI 답이 “이대로 만들까요?”(만들기 제안 `offer`)였고 사용자가 수정 없이 짧게 동의(“좋아요”, “네 만들어줘”, “ㄱㄱ”)하면 그 제안대로 실행한다(5.5). 명확한 생성 요청이나 생성 버튼은 실행 의도로 취급하고 같은 내용의 추가 승인을 반복 요구하지 않는다. 실제 모델·비율 등 필요한 값이 없을 때만 짧게 보완한다.

### 5.4 언어와 기본값

담당자와의 대화는 한국어를 기본으로 한다. 미국 마케팅 작업의 소비자용 결과물 언어는 영어를 초기 제안으로 표시하고 채팅에서 바꿀 수 있게 한다. 목적·타깃·구도 등 AI 기본 제안은 사용자 확정으로 기록하지 않는다. 화면에 표시된 기술 기본값(비율 등)은 생성 요청의 설정 스냅샷에 포함한다.

### 5.5 하나로 합친 대화 — 흐름 가이드 · 보기 칩 · 만들기 제안 · 레퍼런스 (2026-10-24 개편)

예전의 인터뷰(보기 ①②③ 카드)와 자유 대화를 **하나의 대화**로 합쳤다. 시트로 시작하면 AI가 시트를 확인하고 흐름의 첫 질문으로 대화를 연다. 지침은 `prompts.CONVERSATION_CORE_V3`(버전 `reboot-content-v3.1` — 2026-10-25 슬로건 2개 · 비율 질문 · 캡션 자동 추천).

**콘텐츠별 흐름 가이드** (`options.CONTENT_FLOWS` → 화면 `campaign.flow`). 순서는 권장일 뿐이다. 이미 정해진 항목은 건너뛰고, 한 번에 여러 개를 말하면 모두 반영하고, 좋은 콘텐츠에 필요하면 목록에 없는 질문도 한다.

| 콘텐츠 | 흐름 |
| --- | --- |
| 이미지 | 컨셉 · 레퍼런스(`concept`) → 스토리(`story`) → 글로 된 시안 설명(`design_note`) → 강조할 내용(`emphasis`) |
| 카드뉴스 | 담을 내용(`content_points`) → 컨셉 · 레퍼런스 → 강조할 내용 → 장 수(`slide_count`) |
| 숏폼 영상 | 컨셉 · 레퍼런스 → 길이(`duration`) → 스토리 → 시안 설명 → 강조할 내용 |
| CRM | 형식 → 톤 → CTA → 받는 고객 (기존과 같음) |
| + Instagram · TikTok | 만들기 전에는 묻지 않는다. 초안을 만든 뒤 캡션(`caption`) · 멘트(`hook` — 게시글 첫 줄 훅 · 고정 댓글)를 다듬자고 제안하고 원하면 3안 추천 |
| 비율 · 크기 (이미지 · 카드뉴스 · 숏폼) | 2026-10-25 변경: **챗봇이 물어본다**(흐름 마지막 · 숏폼은 길이 다음). 보기 3개는 채널별(`options.ratio_options`)이고 첫 번째가 채널 추천이다 — Instagram 4:5 세로 1080×1350 · TikTok 9:16 세로 1080×1920 · 쇼핑몰 1:1 정사각 2000×2000 · 숏폼 9:16. 캠페인을 만들 때 넣는 채널 기본값(`CHANNEL_RATIOS`, proposed)은 그대로지만 확정이 아니라서 질문 카드 · 대화 모두 묻는다. 실제 이미지는 모델이 지원하는 크기 중 가장 가까운 것으로 만들고, 다르면 결과에 "게시 전 크롭 필요"를 표시한다 |

| 항목 | 기준 |
| --- | --- |
| 질문 | 한 번에 핵심 질문 하나(짧은 보조 질문 하나까지). 열린 질문이 기본이고, 비율 · 장 수 · 길이처럼 답이 좁혀지는 질문에만 **보기 칩**(2~4개, `payload.chips`)을 붙인다. 칩을 누르면 그 글이 사용자 메시지로 간다. 칩은 가장 최근 AI 답에서만 누를 수 있다 |
| 목적 | 시트에 있으면 묻지 않는다. 비어 있으면 따로 캐묻지 않고 대화에서 알아내 후보 카드로 제안한다 |
| 시안 설명 | 실제 이미지를 만들지 않고 배경 · 구도 · 제품 배치 · 색 · 조명 · 소품 · Rebu 여부를 글로 제시한다 (비용 없음) |
| 채널 특성 | 선택한 채널의 특성(`prompts.CHANNEL_PROFILES`)을 매 턴 맥락에 넣어 질문 · 크기 추천 · 톤 · 캡션에 반영한다. Global Olive Young은 입점한 것으로 본다. 플랫폼 규정은 운영 전 최신 확인 대상 |
| 저장 | 답은 흐름 항목 키로 결정 사항(`decisions.<키>`)에 저장한다. 오른쪽 **기획 메모** 표가 같은 값을 보여 준다 |
| 만들기 제안 | 핵심 항목이 대부분 차면 AI가 브리프를 요약하고 “이대로 만들까요?”라고 묻는다(`payload.offer` — 만들 작업 · 한 줄 요약). `만들기` 버튼을 누르거나 “좋아요”처럼 수정 없이 짧게 동의하면 서버가 그 제안대로 실행한다(`heuristics.is_agreement`). 수정이 섞인 답(“좋아요 근데 배경은 흰색으로”)이나 제안 없는 “좋아요”는 실행하지 않는다. 첫 답변과 실행한 턴에는 제안을 띄우지 않는다 |
| 질문 카드 (인터뷰) | **실제 동작(2026-10-25 확인): `이 정보로 시작`은 질문 카드(`/interview` · 보기 ①②③ + 직접 입력)로 시작한다.** 질문은 확정된 값 · 시트 목적을 건너뛰고, 캡션 · 멘트는 묻지 않는다. 비율 · 크기는 2026-10-25부터 채널 추천 보기로 묻는다. 카드 안에는 만들기 버튼을 두지 않고 결과 칸으로 안내한다 |

**레퍼런스 이미지** — 입력창 아래 `레퍼런스 이미지` 버튼으로 올린다.

| 항목 | 기준 |
| --- | --- |
| 형식 · 개수 | JPG · PNG · WebP, 캠페인마다 3장. 화면이 올리기 전에 긴 쪽 1024px JPEG로 줄인다(서버에 이미지 처리 패키지를 두지 않음). 서버는 5MB · 가로세로 16~4096px · 파일 머리를 검사한다 |
| 저장 | 표 `content_references`(파일 · 크기 · 메모 · AI 요약). 파일은 업로드 폴더, `GET /api/content/files/<이름>`으로 본다. 레퍼런스를 지우거나 캠페인을 지우면 파일도 지운다 |
| AI 요약 | 올릴 때 대화 AI가 한 번 보고 4~6줄로 요약한다(`prompts.REFERENCE_V1`). 키가 없거나 실패해도 이미지는 남고 경고만 띄운다 |
| 대화에서 | 요약은 매 턴 맥락(`user_references`)에 넣는다. 이미지 자체는 **마지막 AI 답 뒤에 새로 올린 것**과 사용자가 “레퍼런스 · 참고 이미지”를 말한 턴에만 함께 보낸다(비용 절약). 그 답에는 `레퍼런스 이미지 n장을 보고 답했어요`를 표시한다 |
| 쓰는 범위 | 분위기 · 구도 · 색감 · 촬영 방식만 참고하고 다른 브랜드의 로고 · 문구 · 캐릭터 · 디자인은 옮기지 않는다. **이미지 생성의 참고 사진으로는 넣지 않는다**(제품 · Rebu 참고 사진은 3.5 그대로) |
| 호출 | 공용 `openai_json`은 텍스트만 보내므로 콘텐츠 탭 `providers.call_json_images`가 같은 모델로 부른다. 사용량은 공용 작업 로그(`server.worklog`)에 `AI 프롬프트`로 같은 형식으로 남긴다 |

API: `POST /api/content/campaigns/<id>/references` (multipart: `file`, `note?`) · `DELETE /api/content/campaigns/<id>/references/<rid>`.

## 6. 대화 화면과 실시간 결정 사항

| 영역 | 표시 |
| --- | --- |
| 오른쪽 위 버튼 | `제품 근거`(선택 브랜드·제품의 사실 근거 창) · `AI 설정`(모델 · 고급 옵션 창) |
| 상단 | 자동 캠페인명, **API 연결 상태**(OpenAI · Higgsfield, `연결 테스트`), 대상 칩 여러 개, 콘텐츠·채널, 저장 상태 |
| 왼쪽 | 대화, 보기 칩, 만들기 제안 카드, 추천 선택 카드, 빠른 수정 버튼, 레퍼런스 이미지 |
| 대화 아래 (넓게) | **진행 과정 & 결과**: 단계, 큰 미리보기, 이미지 수정, 생성 버튼, `완성하기`, 버전 목록 |
| 오른쪽 | **기획 메모** 표(콘텐츠별 흐름 항목 · 지금 값 · 정함 / AI 추천 / 아직). 만들기 버튼은 두지 않는다 — 만들기는 결과 칸과 대화의 `이대로 만들까요?` 카드에서만 |
| 접이식 | 기본 정보 시트 수정 |

완성: `완성하기`는 보고 있는 버전을 최종본으로 정하고 캠페인 상태를 `완료`로 바꾼다. 완성된 뒤 다른 버전을 보고 있으면 `이 버전으로 완성하기`로 최종본을 바꾼다. 완성되면 결과 위에 `이미지 저장하기`(텍스트 레이어를 합성한 PNG 다운로드 · 텍스트 결과물은 `파일 저장하기`) · `더 수정하기`(상태만 `제작 중`으로, 최종본 지정은 유지) · `다른 채널로 만들기`(CRM 제외) · `새 콘텐츠 만들기`(시트 처음 화면) 버튼을 둔다.

상태 (2026-10-25): 상단 바의 상태는 읽기 전용 배지다. `완성하기` → 완료, `더 수정하기` → 제작 중으로 자동으로 바뀐다. 상태 드롭다운과 결과 아래 `최종본 지정/해제` 버튼은 없앴다. `검토 중`은 화면에서 고를 수 없고 예전 캠페인 값과 내 캠페인 필터에만 남는다(서버 API는 그대로).

**다른 채널로 만들기** (2026-10-25): `POST /api/content/campaigns/<id>/copy {channel}` — 시트(콘텐츠 · 대상 · 목적 · 추가 요청)와 정한 내용을 복사한 새 캠페인을 만들고 채널만 바꾼다. 비율은 새 채널 기본값 제안으로 바꾸고, 캡션 · 멘트(`routes.COPY_SKIP_DECISIONS`)와 대화 · 버전 · 레퍼런스 파일은 복사하지 않는다. 원래 캠페인의 최종본(텍스트가 아니면 가장 최근 텍스트 버전) 문구를 새 캠페인의 참고 문구로 넣는다. CRM 캠페인 · CRM 채널 · 같은 채널은 거절한다. 화면은 새 캠페인을 열고 바로 초안을 만든다.

API 연결 상태: OpenAI는 키 유무와 모델명을 보여 주고 `연결 테스트`는 모델 조회만 한다 (생성 비용 없음). Higgsfield는 키 유무와 이미지·영상 모델을 보여 주고, `연결 테스트`는 없는 요청 ID의 상태를 조회해 키만 확인한다 (생성 비용 없음).

`확정`은 사용자 입력·선택·명확한 요청, `제안`은 채택 전 AI 후보, `미정`은 아직 없는 값이다. (화면 표시는 2026-10-25부터 `정함` / `AI 추천` / `아직`, 데이터 값 `confirmed` / `proposed` / `undecided`는 그대로. 화면 용어: 브리프 → 기획 메모, 기준 버전 → 고치는 중 · `이 안 고치기`, 결정 사항 → 정한 내용. 서버가 대화에 남기는 이벤트 문구는 바꾸지 않았다.) 각 값에 출처 메시지·사용자·시간·리비전을 기록한다. 최근 변경을 잠깐 강조하고 되돌리기를 제공한다.

모델은 구조화된 결정 변경안을 제시하고, 서버가 허용 필드·대상 ID·근거·현재 리비전을 검증한 뒤 저장한다. 채팅의 “반영했어요”와 오른쪽 상태는 저장 성공 후 함께 확정한다. 실패 시 반영했다고 말하지 않는다. 동시 수정은 충돌을 알려 주며 조용히 덮어쓰지 않는다.

현재 결정과 생성 시점 설정이 달라지면 `변경 사항 미반영`을 표시한다. 캠페인명처럼 생성에 영향 없는 값은 비교에서 제외한다. 늦게 완료된 옛 작업은 해당 버전으로 저장하며 현재 최종본을 자동 교체하지 않는다.

## 7. 생성·수정과 내부 지침

### 7.1 결과물별 처리

| 콘텐츠 | 제작·수정 |
| --- | --- |
| 이미지 | 채팅에서 생성 → 결과 표시 → 기준 이미지를 넣어 편집하거나 합성 레이어 수정 |
| 카드뉴스 | 장별 ID와 문구·제품·배경 레이어. “2장만 수정”이면 다른 장 보존 |
| 숏폼 영상 | 대본·장면·자막·카메라 구성 → 선택 시 실제 생성. 클립과 완성 편집본 구분 |
| CRM 메시지 | 이메일·SMS 문안·시퀀스 초안. 실제 발송은 이 모듈의 기능이 아님 |

**캡션 · 해시태그 자동 추천** (2026-10-25 추가): 이미지 · 영상 생성이 끝나면 서버가 대화 AI를 한 번 더 불러 **캡션 3안**(서로 다른 접근)과 **해시태그**를 받아 그 버전에 저장한다(`media.suggest_social` · `prompts.SOCIAL_V1` · 버전 `snapshot.social`). 결과 미리보기 아래에 카드로 보이고 안마다 `복사`(캡션 + 해시태그) · `해시태그 복사`가 있다.

| 항목 | 기준 |
| --- | --- |
| 근거 | 이미지는 완성된 이미지를 AI가 직접 본다. 영상은 파일을 볼 수 없어 영상 장면 설명(프롬프트 · 메모)으로 쓰고 화면에 그렇게 표시한다 |
| 채널 | Instagram 해시태그 5~8개 · TikTok 3~5개 · 쇼핑몰은 상세 · 배너용 짧은 문구 + 검색 키워드형 태그 3~5개 (채널 특성 `CHANNEL_PROFILES`) |
| 검사 | 캡션 · 해시태그에 키워드 확인을 돌려 결과를 함께 보여 준다(참고용 · 법적 승인 아님). 사실 · 슬로건 규칙은 대화와 같다 |
| 비용 · 실패 | 텍스트 AI 호출 1번(이미지 1장 포함). 키가 없거나 실패해도 이미지 · 영상은 그대로 저장하고 "추천 없음"만 표시한다. 다시 생성하지 않는다 |

이미지 빠른 버튼은 `배경 변경 / 문구 수정 / 제품 크기·배치 / 스타일 변경 / 비율 변경 / 다른 시안`을 제공한다. 버튼도 같은 대화 명령 처리 경로로 기록한다.

생성된 이미지 아래에는 두 가지 수정 방법을 둔다. 둘 다 **새 버전**을 만들고 원본 버전과 부모로 연결하며 원본은 지우지 않는다.

| 방법 | 내용 | 비용 |
| --- | --- | --- |
| AI로 수정 | 수정 요청 입력(빠른 버튼으로 예시 채우기) → 이 이미지를 기준 이미지로 넣어 편집. `AI로 다른 시안`은 기준 없이 새로 생성 | 이미지 생성 비용 |
| 직접 편집 | 브라우저 편집기: 자르기·비율(원본/1:1/4:5/9:16/16:9)과 위치, 밝기·대비·채도, 텍스트 레이어(문구·크기·색·정렬, 끌어서 이동, 추가·삭제). 기본은 레이어를 따로 저장, 선택하면 글자를 이미지에 합성 | 없음 (AI 아님) |

직접 편집의 슬로건 레이어는 원문(`Restart Your Day`) 고정이다. 저장은 `POST /api/content/campaigns/<id>/images` (PNG만 · 12MB · 16~4096px, 서버가 레이어 값 범위를 검사하고 키워드 확인을 기록).

편집은 `base_asset_version_id`, 수정 대상, 유지할 요소, 실제 기준 파일을 전달한다. 편집 미지원 모델로 프롬프트만 다시 보내고 원본 수정이라고 표시하지 않는다. 해당 경우 지원 모델 선택 또는 새 시안임을 알린다. 이전 버전에서 수정하면 부모 버전을 연결해 분기를 보존한다.

### 7.2 로고·제품·문구 보존

PDF의 자산 고정·분리 방식에서 다음을 적용한다.

- 로고는 가능한 한 첨부 원본을 합성한다. 생성 모델에 글자를 다시 그리게 하는 것만으로 보존을 보장하지 않는다.
- 2026-10-25 변경: 새 이미지는 이미지 AI가 헤드라인·슬로건·CTA를 그림과 어울리는 서체로 **직접 그린다**(기본 `글자 넣기`). 그린 문구는 `image_text`로 따로 저장해 키워드·문구별 컴플라이언스 검사에 쓰고, 실제 그려진 철자는 게시 전 사람이 확인한다. 문구를 고칠 때는 `이 이미지 수정하기`에서 AI에게 말한다(`문구 수정` 칩 · 기준 이미지를 넣어 새 버전). `글자 없이`를 고르거나 메시지에 "글자 없이"라고 쓰면 글자 없는 이미지를 만든다. 직접 편집기는 자르기·색 보정만 한다. 예전에 만든 텍스트 레이어 버전은 그대로 보여 주기만 한다.
- 제품 패키지는 최종 패키지 사진(3.5)을 참고 이미지로 넣고, 병·봉지·젤리 모양·라벨을 사진과 같게 그리도록 지시한다(`input_fidelity: high`, gpt-image-1). 그래도 라벨 글자가 일그러질 수 있어 결과에 "라벨 글자·모양은 게시 전 확인"을 표시한다. 참고 사진을 받지 않는 이미지 모델이면 브랜드 키트의 외형 설명으로만 만들고 그렇다고 표시한다.
- 영상은 장면별로 목적·길이·화면·움직임·자막·기준 자산을 정한다. 로고·자막·CM송 합성은 실제 후처리 지원 여부를 확인한다.
- “제품 유지”라는 자연어 지시만으로 수정 영역 밖 픽셀 보존을 보장하지 않는다.

### 7.3 첨부 MD 적용

| 첨부 파일 | 사용할 내용 | 바꿔야 할 부분 |
| --- | --- | --- |
| `1README(1).md` | 지침 파일의 목적·입력 변수·모듈 분리 | 과거 모델·제품 맥락은 최신 기준으로 대체 |
| `1campaign-plan(1).md` | 기획 10개 항목, 메시지와 근거 연결 | 모든 채팅에서 상세 기획 필수로 요구하지 않음 |
| `1draft-content(1).md` | 채널별 필드, 서로 다른 카피 안, 근거 ID | 현재 선택 제품 배열·언어·제안 수 반영 |
| `1brand-review(1).md` | 말투·표기·일관성, before/after | 보조 검토 범위 명시, 외부 판정이 없으면 미연동 |
| `1email-sequence(1).md` | CRM 목적·메시지·간격·조건 구조 | 할인·연락처·개인화 값 창작 금지, 발송 기능 추가 안 함 |

원문의 숙취·수분·전해질·원산지·성분·사용법 등 표현을 새 제품 사실로 자동 이관하지 않는다. 추천 CTA·카피도 근거 없는 결과 보장으로 치환하지 않는다. 첨부 MD의 법령·플랫폼 설명은 운영 시 별도 최신 확인 대상으로 둔다. 이 설계는 법적 준수나 승인 판정을 제공하지 않는다.

내부 템플릿 입력 변수(`factsheet`, `slots` 등)는 서버가 구조화 데이터로 채운다. 입력용 미치환 변수는 오류로 처리하고, CRM 출력용 `{{first_name}}`, `{{unsubscribe_link}}` 등 허용 토큰은 보존한다. 업로드 문서는 참고 데이터이며 시스템 규칙을 바꾸는 지시가 아니다.

첨부 MD의 출처·라이선스 주석은 보존한다. 원본 라이선스 파일은 이번 첨부에 없으므로 코드 배포 시 실제 원본 출처와 고지 조건을 확인한다.

## 8. API·작업 처리

OpenAI는 대화·텍스트·구조화 결과와 지원 이미지 생성·편집에 사용한다. Higgsfield는 지원 이미지·영상 모델을 연결한다. 구체적인 모델 ID·파라미터·길이·오디오 옵션은 모델별 공식 사양과 계정 권한으로 검증한다.

| 내부 책임 | 처리 |
| --- | --- |
| 대화 서비스 | 최신 상태 읽기, 의도·변경안 받기, 검증·반영 |
| OpenAI 어댑터 | 구조화 응답, 작업별 텍스트 생성·보조 검토, 이미지 요청 |
| Higgsfield 어댑터 | 생성 제출·상태 조회·지원 취소·참조 업로드 |
| 작업 큐·워커 | 장시간 미디어 작업, 결과 수신, 파일 보관 |
| 공통 검토 연결 | 팀 검토 서비스가 있을 때 해당 계약으로 연결 |

OpenAI의 구조화 출력은 형식 제약에 활용한다. 형식이 맞아도 사실 정확성·사용자 의도·허용 작업은 서버가 검사한다. 거절·불완전 응답·형식 오류일 때 결정 사항을 변경하지 않는다. 도구 호출도 실행 요청안이며 서버가 인자·권한·실행 의도를 확인한다.

Higgsfield 공식 Quick start의 제출→상태 확인→결과 수신 패턴을 어댑터에 적용한다. 취소는 제공사에 실제 취소 요청을 전달했을 때만 취소 요청 상태로 기록하고, 응답을 받은 후 완료 상태를 정한다. 폴링 중단만으로 취소됐다고 말하지 않는다.

작업 상태는 `queued / running / submission_unknown / saving / succeeded / failed / cancel_requested / canceled`를 구분한다. 명확한 생성 요청 또는 버튼으로 실행하고, 설정 설명·단순 칭찬·AI 추천만으로 미디어를 생성하지 않는다.

- 캠페인·요청 ID로 중복 클릭과 재전송을 막는다.
- 외부 제출 직후 타임아웃이면 `submission_unknown`으로 조회·대조한다. 무조건 다시 제출하지 않는다.
- 외부 작업 완료와 내부 파일 저장 완료를 구분한다. 저장 실패는 파일 보관만 재시도한다.
- 일시 오류는 제한된 재시도, 인증·입력 오류는 즉시 원인을 안내한다. 모델·제공사를 조용히 바꾸지 않는다.
- 사용량·추정 비용·실제 청구액을 구분한다. 알 수 없는 비용을 임의로 표시하지 않는다.
- 프롬프트·모델·파라미터·부모 버전·사용량·오류·소요 시간을 기록한다. 키와 서명 URL은 제외한다.

| 데이터 | 주요 내용 |

| Message / DecisionEvent | 대화·추천 카드·필드 변경 이력 |
| AssetVersion | 결과물 파일, 부모 버전, 입력·설정 해시, 제품별 근거 |
| GenerationJob | 외부 요청 ID, 상태, 요청 중복 방지 키, 사용량 |

| GraphCheckpoint | 대화 재개용 상태, 캠페인 ID·업무 리비전 연결 |

브라우저 세션과 요약 문장은 데이터 원본이 아니다. 업무 DB의 시트·결정·버전을 원본으로 하고 LangGraph 체크포인트는 재개 지점으로 사용한다. 매 턴 최신 업무 리비전을 확인한다. 재개 시 유료 작업이 재실행되지 않도록 작업 키와 outbox 등 일관된 제출 구조를 구현한다.

내 캠페인은 **채널별 폴더**(전체 · Instagram · TikTok · Amazon · Weee · Yami · Global Olive Young · CRM)로 나눠 보여 준다. `전체`는 채널별로 묶어 보인다. 카드 대표 그림은 최종본(없으면 가장 최근) 이미지 · 영상이고, 영상이면 첫 장면을 소리 없이 썸네일로 보여 주고 ▶ 표시를 붙인다(2026-10-25). 카드마다 `삭제` 버튼(만든 사람·관리자만, 확인 후 대화·버전·이미지 파일까지 삭제)이 있다. 이름·대상 여러 개·콘텐츠·채널·상태·수정일로 검색한다. 열면 시트, 대화, 결정, 기준 버전, 진행 작업, AI 설정을 복원한다. 결과 수정은 항상 새 버전을 만든다. 최종본 선택은 최신 버전 선택과 별개다.

텍스트 검토는 브랜드 표기·선택 제품별 근거·금지된 내부 표현을 확인한다. 키워드 확인과 모델 보조 검토, 외부 검토 결과를 분리 표시한다.

**게시 전 체크** (2026-10-25 추가): 검토 칸 맨 위에 한 줄 요약을 둔다 — 키워드 확인 · 컴플라이언스(버전 전체 · 문구별) · AI 보조 검토 · 확인 필요 목록 중 가장 나쁜 결과를 `사용 불가 n곳` / `수정 필요 n곳` / `확인 필요 n곳` / `걸린 항목 없음` / `아직 검사 전`으로 보여 준다. `걸린 항목 없음`도 "게시 가능"이 아니라 "사람이 확인한 뒤 게시"로 안내한다(법적 승인 아님). `모두 검사`는 비용 없는 규칙 검사(버전 전체 + 문구별)만 실행하고 AI 보조 검토는 따로 누른다. 세부 결과는 그 아래 접기(`세부 검사 결과`)에 두고, 걸린 것이 있으면 펼쳐 보인다.

**문구별 컴플라이언스** (2026-10-24 추가): 선택한 버전 아래 `문구별 컴플라이언스`에서 초안을 소비자에게 보일 문구 단위(헤드라인 · 서브라인 · 캡션 · CTA · 해시태그 · 카드뉴스 장별 문구 · 숏폼 자막 칸 · CRM 제목·본문 · 이미지 텍스트 레이어)로 나눠 `검사` / `모두 검사`한다. Visual note · 화면 · 카메라 · 기준 자산 · 총 길이처럼 담당자용 칸은 제외한다. 검사는 컴플라이언스 탭이 공개한 `REBOOT.use('compliance').review()`를 브라우저에서 불러 쓰며(비용 없음, 컴플라이언스 탭 코드는 고치지 않음), 걸린 단어를 문구 안에 표시하고 대체 문구를 보여 준다. 문구별 결과는 화면에만 두고 서버에 기록하지 않는다(버전 전체 `검사하기` 결과는 기존대로 기록). 결과는 1차 참고 판정이며 법적 승인이 아니다. 외부 검토 미연동은 `미연동`, 검사 오류는 `미검토`로 표시하며 통과로 대체하지 않는다.

카피·제품 사실·참고 자산이 바뀌면 관련 결과물을 재검토 대상으로 표시한다. 텍스트만 검사했으면 이미지 속 글자·영상 전체도 검사했다고 말하지 않는다. 최종본 지정은 법적 승인이나 사실 확인 완료를 의미하지 않는다.

초안 다운로드는 미검토·임시·시안 상태를 파일에 함께 남긴다. 팀 승인본 내보내기는 기존 대시보드 승인 정책을 따른다. 무조건 모든 파일을 승인본으로 이름 붙이지 않는다. ZIP에는 선택 버전의 결과·설정·근거·검토 요약을 넣고 비밀값은 제외한다.

## 10. 구현 경계와 환경변수

기존 대시보드의 프레임워크·로그인·DB·UI를 재사용한다. 첨부만으로 Flask나 Streamlit 운영 구조를 확정하지 않는다. Streamlit 시제품이 있어도 그 세션 상태를 운영 저장소로 사용하지 않는다.

권장 모듈은 `ui`, `schemas`, `conversation`, `prompts`, `providers`, `jobs`, `repositories`다. 이미 같은 책임의 계층이 있으면 중복 생성하지 않는다. 데이터·제공사 어댑터를 대화 그래프와 분리해 프레임워크 교체가 가능하게 한다.

로컬 개발의 `.env`는 앱 폴더 **상위 폴더**에서 읽는다. 아래 경로 예시는 `config.py`가 `dashboard/` 바로 아래에 있는 경우다.

```python
from pathlib import Path
from dotenv import load_dotenv

APP_ROOT = Path(__file__).resolve().parent
load_dotenv(APP_ROOT.parent / ".env", override=False)
```

```dotenv
# 앱에서 정의할 설정 이름. 실제 비밀값은 넣지 않는다.
OPENAI_API_KEY=
HIGGSFIELD_API_KEY=
CONTENT_TEXT_MODEL=
CONTENT_IMAGE_PROVIDER=openai
CONTENT_IMAGE_MODEL=
CONTENT_VIDEO_PROVIDER=higgsfield
CONTENT_VIDEO_MODEL=
DATABASE_URL=
QUEUE_URL=
ASSET_STORAGE_BUCKET=
```

별도 writer/review 모델 환경변수는 요구하지 않는다. Higgsfield 키 변수는 서버 어댑터가 공식 인증 방식으로 전달한다. 위 이름이 제공사 SDK에서 자동 인식되는 변수명이라는 뜻은 아니다.

운영 비밀값은 서버 환경변수·비밀정보 저장소로 주입한다. 키를 채팅·캠페인·브라우저 저장소에 넣지 않는다. 모든 캠페인·작업·다운로드는 서버에서 소유 조직과 권한을 확인한다. 참고 파일은 형식·크기를 검사하고 모델 출력은 실행 코드로 취급하지 않는다.

### 내부 API 계약 예시

| 작업 | 입력·반환의 핵심 |
| --- | --- |
| 캠페인 생성·수정 | 시트, `brand_focus`, `product_ids[]`, `expected_revision` |
| 추천 | 요청 필드·현재 리비전 → 후보 3개·이유 |
| 대화 | 메시지·리비전·기준 버전 → 답변·반영된 결정·다음 행동 |
| 생성·수정 | `client_request_id`, 리비전, 기준 결과물, 설정 → `job_id` |
| 작업 조회 | `job_id` → 상태·오류·완료 결과 버전 |
| 캠페인 복원·내보내기 | 권한 확인 후 일관된 상태·선택 버전 파일 |

위 이름은 내부 설계이며 외부 SDK 함수명이나 이미 구현된 엔드포인트가 아니다.
